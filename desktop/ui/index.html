      Tilslut din AI
      Modellen kan køre lokalt, hos en udbyder eller på jeres egen server. Arbejdsområdet ligger fortsat på denne computer.
      

      1. Åbn din udbyders konto og find API-nøgler. En API-nøgle giver appen adgang til din AI-konto. Forbrug kan koste penge hos udbyderen.
      2. Kopiér nøglen, og indsæt den nedenfor. Har du fået adgang af din arbejdsplads, skal du bruge deres oplysninger.
      3. Gem forbindelsen. Du kan derefter hente modeller og gennemgå databehandlingen før din første besked.
      Avanceret · navn og serveradresse
      Eget kompatibelt API: medtag normalt /v1. Ollama: serveradressen uden /v1. Tailscale skal allerede være forbundet.
      Claude-abonnement er endnu ikke understøttet. Nøgler er indstillinger, ikke skill-indhold.
      

      Data og vilkår før afsendelse
      Oplysningerne nedenfor er ikke en sikkerhedsgodkendelse. Ukendte vilkår er tydeligt angivet; du vælger selv forbindelsen.
      Se databehandling, pris og aktive regler
      

      Skills og regler
      Tilpasninger gælder dette projekt og gemmes i appens datamappe. Aktive skills sendes som instruktioner til agenten. De er ikke tekniske adgangsbegrænsninger. Skriv aldrig nøgler her.
      Tekniske begrænsninger
      Appen beskytter modelnøgler og preview. Agentens filændringer, kommandoer, webopslag og adgang uden for projektet kræver godkendelse. Skills kan ikke ophæve disse kontroller. Agentprocessen er ikke en OS-sandbox. Kommunal styring og cloud-arbejdsområder er endnu ikke tilsluttet.
      

      Filændringer siden første besked
      Oversigten kan også indeholde dine egne samtidige ændringer. Store filer, binære filer, afhængigheder og kendte hemmelighedsfiler er udeladt. Automatiske checkpoints kræver aktivt tilvalg under Gem version.
      

      Lokal udviklingsserver
      Appen starter ingen kommando automatisk. Kun den valgte lokale servers netværksadresse tillades i forhåndsvisningen. Serverens HTML kan afvise indlejring.
      

      Versioner · lokal Git
      Hvem gemmer versionerne?
      Navn og e-mail bliver synlige i versionshistorikken, også hvis projektet senere deles. Oplysningerne gemmes kun i dette projekt. Brug eventuelt din GitHub-noreply-adresse.
      

      Versioner gemmes i projektets almindelige Git-historik. Intet pushes eller udgives. Du kan senere bruge din egen Git-server eller organisation, herunder AI Alliancen.
      


      Kræver rent udgangspunkt og genkendelige filændringer. Fejl, stop, afvisninger, kommandoer og uklare ændringer springes over. Undgå samtidige filændringer fra andre programmer. Et checkpoint betyder gemt, ikke testet eller godkendt. Valget gælder dette projekt.

          Flere steder at udgive · endnu ikke tilsluttet

          Disse destinationer kræver nye adaptere. De kan ikke vælges til upload i denne version.
          

          • Cloudflare Pages / Workers: preview-adresser til hjemmesider og kompatible Workers-apps.
          • Netlify: draft-udgivelser til hjemmesider og understøttede funktioner.
          • Render: testmiljøer med tjenester og datalagre.
          • Railway: særskilte miljøer til appens tjenester.
          • Egen server: fx kommunens infrastruktur eller en server hos Hetzner. Kræver egen opsætning af runtime, testadresse og adgang.
          

          Et testmiljø er ikke automatisk gratis, privat eller placeret i Danmark. Vilkår og adgang skal kontrolleres for den konkrete konto og opsætning.
          

          Bruger dit eksisterende login i Vercel CLI eller Azure CLI. Værktøjerne skal være installeret og tilsluttet på denne computer. Vercel kræver en eksisterende startversion i projektet; tomme projekter afvises for at undgå automatisk produktionsudgivelse. Azure kræver også SWA CLI og en eksisterende Static Web App. Appen opretter ingen cloudressourcer. SWA CLI kan hente sit deploymentværktøj ved første upload.
          


          

          Testmiljøet hedder harness-test. En ny udgivelse erstatter indholdet i dette testmiljø.
